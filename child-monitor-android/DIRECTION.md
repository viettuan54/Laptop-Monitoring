Mode: Operate. Native Android phone app extending the established LaptopChildren web identity. The user accepted the implementation plan and requested construction and installation on a connected Redmi K30. Existing web-only constraints in root PRODUCT.md describe earlier web work; this explicit request authorizes a separate Android client.

## Direction contract

THESIS: Let a parent identify the child, understand recent laptop use, and act on an alert in one compact flow.

OWN-WORLD: Inherit web blue #174EA6, ink #11233F, pale #F4F7FB and white; translate into Material 3 light/dark roles, system Roboto, 48dp controls and quiet separators.

STORY: Sign in with the existing parent account, choose a child, review activity, then change an explicitly named policy. Empty, loading, offline and unconfigured-push states are visible and honest.

FIRST VIEWPORT: Login shows a laptop brand mark, LaptopChildren, a short purpose sentence, labelled email/password fields, and one filled login action. Signed-in view shows the child selector above today's usage and recent daily bars, then devices and clear links to alerts. Four bottom destinations follow the accepted plan.

FORM: Direct adaptation of the accepted four-tab structure within the incumbent visual world; no new-world seed or concept tournament. The signature interaction is changing the selected child and updating every dependent section without showing the previous child's data.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance
