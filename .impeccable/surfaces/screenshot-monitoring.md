# Screenshot monitoring — development direction and evidence

Updated 2026-10-09. Scope: the existing Parent Dashboard in `child-monitor-web/app.js` and `child-monitor-web/styles.css`.

## Direction

**Operate.** Extend **Hoạt động** with **Giám sát màn hình**, beside **Ứng dụng** and **Website**. Parents opt in through the existing device controls; the Agent captures the main screen every five minutes by default. **Bắt đầu chụp ảnh** asks the selected device for one fresh image; it does not enable consent or replace the regular schedule. The user confirmed images arrive with Agent 1.0.18 and requested lower latency, greater stability, individual deletion, and clearing all images. This follow-up retains device/date filters, newest-first thumbnails, device and capture time, enlargement, pagination, and useful empty/error/loading feedback while adding the requested deletion controls and more responsive metadata polling.

Preserve the dashboard's blue palette, typography, navigation, buttons, forms, and shared modal behavior. Use three/two/one thumbnail columns for desktop/intermediate/mobile widths. This ordinary extension establishes no new identity, comp, or artwork.

`PRODUCT.md` remains the product context. Its general UI-only constraints do not describe the separately requested Agent/backend feature work in this delivery. Operational behavior and installation instructions live in `child-monitor-agent/docs/screenshot_monitoring.md`; that document is owned by the main implementation handoff, not this surface brief.

| Individual deletion | `confirmScreenshotDelete()` opens the shared confirmation dialog with device and capture time, irreversible-deletion wording, **Hủy**, and a danger-styled **Xóa ảnh** action. | Clear-all scope | `confirmClearScreenshots()` reads the visible device selection before **Áp dụng**. A selected device limits deletion to that device; **Tất cả thiết bị** includes all devices owned by the account. It fetches fresh scope metadata without date filters and shows the count, scope, inclusion of images outside the time filter, irreversible effect, and continued automatic schedule. Loading, empty-scope, and failure/retry states use the shared dialog. |
| New-arrival protection | Clear-all confirmation captures the scope's latest ID from the metadata response and sends it as `through_id` with `confirm_all: true`. The confirmed device scope and upper ID travel with the confirmation button. Images arriving with a higher ID after that snapshot are preserved; date filters and page size do not narrow the confirmed clear-all scope. |
| States and pagination | A status region distinguishes no device, device selection required, monitoring disabled/enabled, waiting online/offline, expired requests, and interrupted connection. Capture is disabled when unavailable or pending; failed submissions restore the action and show an error toast. List errors offer retry; enlargement has loading and expired/error messages. Pagination requests 12 images and corrects an offset that no longer has rows after deletion. |
| Metadata polling | `scheduleScreenshotRefresh()` checks metadata every 2 seconds when any returned device has a pending request, every 15 seconds otherwise, and every 30 seconds after an error. A signature compares counts, latest IDs, scope metadata, and device status. The gallery reloads thumbnails only after a signature change or recovery from an error. Background failures preserve loaded content; successful full refresh clears the error state. Stale responses are guarded. These intervals describe implementation, not measured end-to-end latency. |
| Interaction preservation | Hidden documents, open modals, focused input/select/textarea controls, and keyboard-focused buttons/links (`:focus-visible`) defer polling and automatic replacement. The guard also compares visible device/date values with applied state, preserving unapplied filter drafts after blur. Pointer-focused buttons no longer block automatic updates indefinitely. The interaction guard is checked before polling and again before background rendering so focus or drafts created during a request remain protected. |
